# B站UP主开播监测插件 (astrbot_plugin_bililive)

监测指定B站UP主的**开播状态**和**空间动态**，有变化就推到你指定的群。**每个UP主可以各自配置推送到哪些群**，配置界面和聊天命令双向管理，改一处两边同步。

> 🔱 **源头声明**：本插件的源头项目是 **[astrbot_plugin_bilibiliobs](https://github.com/BB0813/astrbot_plugin_bilibiliobs)**（原作者 **BB0813**），本项目正是在它的代码基础上修改而来，源头与功劳归属原项目。
>
> 原插件使用上不太合手，本项目针对它的一些问题做了重写修复：配置界面看不到订阅、数据乱放导致卸载不清、同一个群开播被多平台重复推送、退订必须记 UID 等。
> 当前版本（v2.2.0）增加**动态推送**：UP主投稿视频/图文/专栏/转发/音频都能推，按类型分别开关，用动态 id 游标判断新旧（不漏也不刷屏）。详见文末更新日志。

## 主要特性

- 🎯 **每UP各自配群**：UP-A 发甲群乙群、UP-B 只发丙群，互不影响
- 🖥️ **配置界面可视化管理**：直接在 WebUI 插件配置里增删「监控UID + 目标群」
- 💬 **聊天命令同步**：群里 `/订阅`、`/退订`、`/订阅列表` 与配置界面共用同一份数据
- 🔢 **退订支持序号**：`/订阅列表` 带序号，`/退订 2` 即可，不用记 UID
- 🚫 **不再重复推送**：目标群显式列出、裸群号只补全到单一平台，从设计上杜绝一次开播发两条
- 🏷️ **@全体按群控制**：每个目标可单独加 `@all`，A 群 @全体不影响 B 群
- 🔕 **通知按群开关**：群管理可用命令只关本群通知，不影响其他群；另有全局静音时段
- 📝 **动态推送（v2.2.0 新增）**：UP主投稿视频、图文、专栏、转发、音频都能推，**按类型分别开关**（只要视频就只开视频）
- 🔁 **动态不漏也不刷屏**：用动态 id 游标判断「新」（按数值比，不怕位数变化），重启不补发存量，单轮最多补 10 条，被风控自动退避
- 💬 **动态命令同步**：`/动态订阅`、`/动态列表`、`/退订动态 2`、`/检查动态` 与配置界面共用同一份数据
- 🛡️ **管理员鉴权**：通知开关、扫码登录受 `admin_ids` 控制，Cookie 失效自动私聊提醒管理员
- 📁 **数据落规范目录**：`data/plugin_data/astrbot_plugin_bililive/`，卸载时能被 AstrBot 一并清理
- 🖼️ **封面图通知（可关）** / 🔔 **关播通知** / 📝 **自定义模板（写错不炸推送）**
- 🍪 **Cookie 支持 + 扫码登录续期**：管理员私聊扫码自动更新 Cookie

## Web 面板（推荐用来配订阅）

AstrBot WebUI → 插件 → B站开播监测 → 打开面板（需要 AstrBot ≥ 4.24.1）：

- **订阅矩阵**：左侧「开播订阅 / 动态订阅」切换，一行一个 UP 主，行内直接挂要推的**群名**标签；
  点「新增 UP 主」或「编辑」弹窗里勾选群（可按群名/群号搜索、「刷新群列表」一次拉齐机器人所在的全部群），
  每个群还能单独勾 `@全体`
- **按群通知开关**：开播 / 关播 / 动态三列，改一下即保存，等价于群里 `/开启通知`、`/关闭通知`
  （同一个群有多种平台写法时只显示一行，改一次会同步到全部写法）
- **运行状态**：HTTP 会话、监控任务、检查间隔（限流退避时显示当前实际间隔）、动态基线数、Cookie 是否配置、静音时段是否生效
- **诊断 + 整理**：原来只能在状态文本里看到「有 N 行无法解析」，现在直接列出原文；另外会提示两类问题并支持一键整理：
  - **同一个群被写成多种平台前缀**（例如 `aiocqhttp:GroupMessage:123` 和 `napcat:GroupMessage:123`）——
    面板标签上会显示平台前缀，发不出去的那个标 ⚠ 并标红；「整理重复与失效写法」会只留能发出去的那个
  - **前缀不是已加载平台实例**（典型是配置里把「默认平台」填成了适配器类型名 `aiocqhttp`，而实际实例 id 是
    `napcat`）——这种订阅发不出去；同一个按钮会把它改写到同类型实例上

订阅矩阵里的群标签现在带**平台前缀**，同一个群如果被写成了两种前缀，一眼就能看出来是同一个群、
以及哪一条是发不出去的。

保存走的是插件原有的 `_save_subs` / `_save_dyn_subs`（序列化 + 落盘 + `groups.json` 剪枝），所以面板、
WebUI 配置页、聊天命令三处改的都是同一份数据，不会互相覆盖。

## 配置项

在 AstrBot WebUI 的插件配置页设置：

| 配置项 | 说明 |
| --- | --- |
| `subscriptions` | **订阅列表**，每行一个UP，格式 `UID=目标[,目标...]`，目标可带 `@all` 后缀 |
| `default_platform` | 裸群号补全到哪个平台**实例id**（留空自动探测第一个平台。填成适配器类型名 `aiocqhttp` 也能用：会自动映射到同类型的实例 id，例如 `napcat`） |
| `check_interval` | 检查间隔（秒），实际生效钳制在 30-600 |
| `max_monitors` | 最大监控 UP 数 |
| `enable_notifications` | 开播通知全局总开关（单群开关用群里命令控制） |
| `enable_end_notifications` | 关播通知全局总开关 |
| `send_cover` | 推送是否附带直播封面图 |
| `quiet_hours` | 静音时段 `HH:MM-HH:MM`（可选，支持跨零点），该时段暂停检查与推送 |
| `admin_ids` | 管理员QQ号列表：通知开关命令鉴权、Cookie失效提醒、扫码登录鉴权 |
| `bilibili_cookie` | B站 Cookie（可选，提高 API 限额；**动态推送建议配**，见下文） |
| `live_notify_template` / `end_notify_template` | 开播/关播通知模板 |
| `dynamic_subscriptions` | **动态订阅列表**，写法与 `subscriptions` 完全一致 |
| `dynamic_check_interval` | 动态检查间隔（秒），钳制 30-600，默认 45；UP多时建议 120 以上 |
| `dynamic_notify_template` | 动态通知模板，占位符 `{uname}` `{action}` `{title}` `{text}` `{url}` |
| `dyn_notify_video` / `_draw` / `_article` / `_word` / `_forward` / `_music` | 各类动态的推送开关（默认开） |
| `dyn_notify_live` | 动态里的「正在直播」卡片（默认**关**，避免与开播监测重复） |
| `dyn_notify_other` | 归类外的动态（投票、播单等，默认关） |

### subscriptions 写法

每个「目标」有三种写法，短的优先：

```
111111111=777777777                # ①裸群号，按 default_platform 补全
111111111=napcat:777777777         # ②平台id:群号（推荐，可多平台混用）
111111111=napcat:GroupMessage:777777777   # ③完整 unified_msg_origin
222222222=napcat:777777777@all               # 只对该群开播@全体成员
111111111=napcat:777777777,default_666666666:777777777   # 同一UP推到多个平台
# 以 # 开头的行是注释
```

- 冒号前是平台的**实例 id**（在 AstrBot「配置 → 消息平台」里看，如 `napcat`、`default_666666666`），**不是**类型名 `aiocqhttp`/`qq_official`
- 目标后加 `@all` 表示该群开播时@全体成员；旧写法「行尾 ` | at_all`」（整行所有群@全体）仍兼容
- 同一UID可写多行，会自动合并群列表
- 格式错误的行会被忽略，在日志和 `/开播监测状态` 里提示
- 保存后会自动统一成 `平台id:群号` 简写

`dynamic_subscriptions` 的写法与它**完全一样**，只是推的是空间动态：

```
222222222=napcat:777777777         # 该UP一有新动态就发本群
222222222=napcat:777777777@all     # 视频/直播卡片类动态@全体，图文/专栏不@
```

## 聊天命令

| 命令 | 说明 |
| --- | --- |
| `/订阅 <UID> [at_all]` | 把**当前群**加入该UP的推送目标（免手填群号） |
| `/退订 <UID或序号>` | 从当前群移除某UP，序号来自 `/订阅列表` |
| `/订阅列表` | 列出本群订阅的UP（带序号和直播状态） |
| `/检查直播 <UID>` | 手动查一次直播状态 |
| `/动态订阅 <UID> [at_all]` | 把**当前群**加入该UP的动态推送目标；自动记下当前最新动态做基线，不补发旧货 |
| `/退订动态 <UID或序号>` | 从当前群移除该UP的动态订阅，序号来自 `/动态列表` |
| `/动态列表` | 列出本群订阅的动态UP（带序号和 `@all` 标记） |
| `/检查动态 <UID>` | 手动拉一次该UP最新动态（展示前3条，用来验证动态接口通不通） |
| `/开播监测状态` | 查看运行状态与生效配置（通知开关、默认平台、动态间隔、坏行警告等） |
| `/开启通知` `/关闭通知` | **本群**通知开关（仅管理员，不影响其他群；关闭后开播/关播/动态都不发） |
| `/开启关播通知` `/关闭关播通知` | **本群**关播通知开关（仅管理员） |
| `/开启动态通知` `/关闭动态通知` | **本群**动态推送开关（仅管理员，不影响开播/关播通知） |

### 管理员

在插件配置 `admin_ids` 里填管理员QQ号（可多个）。管理员可以：

- 在群里用 `/开启通知` `/关闭通知` 等命令控制**本群**通知（其他群不受影响）
- 私聊 Bot 扫码登录续期 Cookie
- Cookie 失效时会收到私聊提醒

未配置 `admin_ids` 时，命令回退用 AstrBot 全局管理员判定；Cookie 失效提醒退回本次运行期间记录过的管理员私聊。

### 管理员扫码登录（私聊Bot）

私聊 Bot 发送 `更新cookie` / `b站登录` / `bilibili登录` / `更新b站cookie`，Bot 返回二维码，B站客户端扫码后 Cookie 自动更新。管理员首次私聊会自动记录身份；Cookie 失效时会私聊提醒。

## 动态推送（v2.2.0）

`dynamic_subscriptions` 管的是 UP 主的**空间动态**，与开播监测各自独立：可以只订开播、只订动态，或两条都订。

- 推送内容：投稿视频（附封面）、图文/相簿（最多3张图）、专栏文章、转发动态（原动态概要拼进正文）、音频、纯文字
- `@all` 只在「视频、直播卡片」两类生效，图文和专栏不 @ 全体，避免刷屏
- 判定「新」用的是**动态 id 游标**：按**数值**比大小（老动态 18 位、新动态 19 位，按字符串比会永远判错），且游标只前进不回退
- 首次见到某个UP（刚订阅、刚重启）只记基线**不补发**存量动态；一次轮询跨太久最多补推 10 条
- 节流：单UP之间间隔 2 秒；被限流时整机间隔翻倍（最多 900 秒）；单个UP连续失败按 60s/120s/… 退避（上限 20 分钟）
- 静音时段（`quiet_hours`）内动态同样暂停收集与推送

### 动态接口为什么要配 Cookie

动态接口（`x/polymer/web-dynamic/v1/feed/space`）对匿名调用很不客气，常见三种情况：

| 现象（日志） | 含义 | 处理 |
| --- | --- | --- |
| `code=-636` | 接口不接受匿名请求，只能拿到部分动态或直接拒绝 | 配 `bilibili_cookie`（管理员私聊Bot发 `b站登录` 扫码最快） |
| `code=-352` / `HTTP 412` | 签名校验/风控 | 插件会自动强制刷新 WBI 密钥重试，再失败就退避；同机轮询过密也会触发，把 `dynamic_check_interval` 调大 |
| `code=-799` | 请求过于频繁 | 同上，调大间隔 |

插件已内置 **WBI 签名**（`wbi.py`）与 **buvid 访客指纹**（一天一刷），这是匿名能读到动态的前提；大V号、锁内容的UP仍需配 Cookie 才能读全。

## 如何获取 UP 主 UID

打开 UP 主 B站主页，URL 里 `https://space.bilibili.com/123456` 中的 `123456` 就是 UID。

## 数据存储

- 订阅、全局开关、Cookie、模板 → 插件配置 `data/config/astrbot_plugin_bililive_config.json`（WebUI 直接可改）
- 运行时状态 → `data/plugin_data/astrbot_plugin_bililive/state.json`
  - `live_status_cache`：每个UP上次的直播状态（重启不误报“刚开播”）
  - `dyn_last_ids`：每个UP已推到的动态 id 基线（重启不补发存量动态）
- 按群通知开关 → `data/plugin_data/astrbot_plugin_bililive/groups.json`（群里命令写入，卸载随目录清理）

两者都在 AstrBot 规范目录下，卸载插件时会被清理干净。

## 本地测试

纯逻辑（WBI 签名、动态解析、订阅串、游标）都拆在无副作用模块里，**不需要装 astrbot** 就能跑：

```bash
python tests/test_subscription.py     # 订阅串解析/序列化/@all
python tests/test_dynamic_report.py   # WBI 签名、动态分类与提取、id 游标
python tests/test_main_smoke.py       # 桩掉 astrbot 拉起 main.py，跑游标/按群推送/消息拼装
```

三个脚本全绿会各打印一行 `OK`，有失败以非零退出码结束，方便挂 CI。
